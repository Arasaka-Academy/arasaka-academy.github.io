## 发布边界与待验收项

本地已具备 GitHub Actions 检查与部署工作流，但 GitHub CLI 原授权失效，设备登录流程的令牌请求又出现网络超时，旧验证码不再有效。需在本机重新完成 `gh auth login --hostname github.com --git-protocol ssh --web`。因此此记录不声称已创建远端仓库、推送代码、通过 GitHub CI 或上线 Pages。

授权恢复后按以下顺序交付：

1. 确认组织建仓及 Pages 管理权限，并检查目标仓库是否已经存在，避免覆盖现有内容。
2. 创建公开的 `Arasaka-Academy/arasaka-academy.github.io`，配置 SSH origin 并推送已验证的 `main`。
3. 将该仓库 Pages 来源设置为 GitHub Actions，等待同一提交的检查与部署真实成功。
4. 比对本地 HEAD、远端 `main` 和部署提交。
5. 对线上 `/`、`/en/`、404、静态资源与浏览器错误另做验收，并确认已有 CyberUI、CyberMachine 项目子站未受影响。

不修改其他项目仓库，不设置自定义域名，不接入追踪统计，也不把软件浏览器验证当作硬件、设备语音或物理制造验收。
