# Arasaka Academy homepage design

## Visual thesis

A black-and-signal-red industrial flagship: an independent cyber laboratory, grounded in real software and hardware rather than fictional telemetry.

CyberUI contributes chamfers, open frames, precise outlines, Oxanium headings, Share Tech Mono readouts, and warm dark/cyan/red semantics. Chinese prose uses an explicitly licensed Noto Sans SC subset. The organization mark is original geometry, not a game asset.

## Content sequence

1. Brand poster: oversized ARASAKA / ACADEMY wordmark, one clear promise, one primary exploration command, and an ecosystem installation.
2. Project ecosystem: six differentiated project exhibits, two larger anchors and four compact entries. Every project has a role, concrete capabilities, media, and a repository link.
3. Inside the work: the actual CyberOS interface with demonstration data, followed by CyberMachine digital assembly. Product and manufacturing acceptance boundaries stay visible.
4. Building principles: human control, a connection to physical reality, and continued exploration.
5. Participation: a direct invitation to read, discuss, and build on GitHub.

## Interaction budget

- A short layered entrance establishes first-screen hierarchy without blocking reading.
- A progressively enhanced Three.js installation responds to small pointer and scroll changes; it renders on demand instead of running a permanent animation loop.
- Project focus and hover reveal a brief scanning edge. Keyboard focus receives the same emphasis.

No audio autoplay, custom cursor, forced horizontal scroll, fictitious live status, promotional metrics, loading gate, or constant glitch animation.

## Progressive enhancement and delivery

The static poster and all text are present in exported HTML. WebGL is an optional desktop layer, not a dependency for understanding or navigating the site. Mobile, data-saving, reduced-motion, and failed-renderer states retain the same composition as a static poster.

Chinese and English are independent static documents with correct language and metadata. The only public interfaces are these documents, their anchors, and the external project destinations. There is no application backend or runtime API.
